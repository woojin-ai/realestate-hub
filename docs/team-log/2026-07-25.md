1. **운영 DB 마이그레이션이 배포보다 먼저여야 한다.** 컬럼이 없는 상태로 새 코드가 배포되면 `upsertMonthDeals` payload에 없는 컬럼이 있어 PostgREST가 `PGRST204`를 낸다. 두 호출부 모두 try/catch라 **사용자 화면은 안 깨지지만**(`/api/data`는 200 유지, 프리워밍은 `upsertOk=false`로 `months_collected` 전진 차단) **그 사이 deals 적재가 조용히 멈추고** 매 조회가 라이브 fetch로 떨어진다. main push = Vercel 자동배포이므로 순서를 뒤집을 수 없다.
2. `.env.local`에 Supabase **REST 키만** 있고 Postgres 직결 문자열이 없어 PostgREST로는 DDL 실행이 불가능하다 → **사용자가 Supabase SQL Editor에서 직접 실행해야 한다.**
3. 부수 문제: `lib/db-cache.ts`에 타 세션의 `/ranking` 작업(`loadRankingMonthlyStats`)이 섞여 있어, 파일 단위 `git add`로는 #3(b)만 분리 커밋할 수 없다. 해당 세션 커밋 후에 담는 것이 깔끔하다.

```sql
alter table deals
  add column if not exists cdeal_type text,
  add column if not exists cdeal_day text;
```
적용 후 알려주시면 코드를 커밋·배포한다. 기존 적재분은 두 컬럼이 null로 남고 이후 재수집되는 월부터 채워지며, 전국 해제 비율 실측은 데이터가 쌓인 뒤 가능하다.
