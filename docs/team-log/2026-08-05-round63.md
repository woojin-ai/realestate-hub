## 8. 이번 라운드에서 새로 세운 표준

### 8-1. 🔴 화면 조작을 처방하는 문장은 그 처방의 결과가 코드로 참인지 확인하고 쓴다

F-2를 일반 규칙으로 승격했다(축자 지시서에 명문화).

> **화면 조작을 독자에게 처방하는 문장은, 그 처방을 따랐을 때 나오는 결과가 코드로 참인지 확인하고 쓴다.** 특히 **라이브 입력 상태를 그리는 컨트롤**(선택 즉시 반영)과 **명시적 조회로만 갱신되는 표시 데이터**가 한 화면에 공존하면, 전자를 후자의 출처 확인 수단으로 안내해서는 안 된다.

**왜 기존 게이트가 못 잡았나**: 이 문장의 구성 사실은 **각각 전부 참**이었다(두 칸은 실재하고, 값은 실제로 남아 있고, 재조회는 실제로 필요하다). **거짓인 것은 그 사실들을 엮은 처방뿐**이다. 사실 단위로 `파일:라인`을 검산하는 기존 절차는 원리적으로 이 유형을 통과시킨다 — **08-04 티켓 #30의 "내부정합 감사는 상수오류를 원리적으로 못 잡는다"와 같은 계열의 사각이다.**

### 8-2. 🔴 결함 2건이 같은 자리에서 나면 원인이 하나일 수 있다

F-1(축자 겹침)과 F-2(사실 오류)는 **서로 독립한 게이트**가 잡았는데 **같은 절**을 가리켰다. 우연이 아니다 — 그 절은 **다른 글(I4)의 마무리 문장을 어투째 가져다 쓴 자리**였고, 그래서 ① 축자가 겹쳤고 ② **이 화면에는 성립하지 않는 처방을 그대로 옮겨 왔다.**

> **표준**: 두 게이트가 같은 구절을 가리키면 각각 고치지 말고 **그 구절이 어디서 왔는지**를 먼저 물어라. 한 번의 교체로 둘 다 닫히면 원인이 하나였다는 뜻이다.

## 9. 사용자 판단/조치 대기

> ℹ️ **푸시 알림을 보내지 않았다.** 라운드59가 3회 연속 미전달(`Remote Control inactive`)을 실측하고 "다시 시도하지 마라, 이 로그가 유일한 전달 경로다"라고 못박았고 라운드60·62가 그 판단을 따랐다. 이번에도 따른다. **새로 발생한 P0도 없다** — 이번 라운드의 블로커는 전부 자체 해결됐다.

### 9-1. [16라운드째, 🔴 가장 오래된 차단] 결정 #3(b) DB 마이그레이션

`deals`에 `cdeal_type`·`cdeal_day` 추가. SQL은 `supabase/schema.sql`에 준비돼 있으나 **미커밋 상태로 16라운드째 동결**이다.

🔴 **순서가 중요하다 — DB 적용이 코드 배포보다 먼저여야 한다.** 컬럼 없이 새 코드가 upsert하면 PostgREST가 `PGRST204`로 적재를 통째로 실패시킨다.

이 동결이 라운드57 §7-2의 작업 4건을 계속 막고 있다.

### 9-2. [라운드58 → 59 → 60 → 62 이월, 🔴] 광주광역시 캐시 리셋

여전히 미해결이고 여전히 **사용자 조치 1회로 끝난다.** 동결과 무관하고 코드 변경도 불필요하며, 이미 배포된 관리자 엔드포인트에 HTTP 5회다.

```bash
for c in 29110 29140 29155 29170 29200; do curl -s "https://realestate-hub-6n4n.vercel.app/api/admin/reset-cache?secret=$CRON_SECRET&lawd_cd=$c&building_type=아파트"; echo; done
```

`$CRON_SECRET`은 `.env.local` 값(로그에 평문으로 적지 않는다). 지우는 5개 지역 행이 **전부 0건**이라 소실될 데이터가 없다. 마스터가 직접 하지 않는 이유는 스케줄 지시서가 이 **쓰기 동작**을 명시하지 않았기 때문이다.

**결과 판독**: 재수집 후 거래가 잡히면 캐시 오염(종결). 여전히 0이면 `LAWD_FANOUT` 등록이 필요하고 그건 `lib/molit-api.ts`(**동결**)라 9-1 해제까지 대기.

🔴 **인천에는 이 리셋을 쓰지 마라** — §2가 보여주듯 원천 데이터 자체가 없어 리셋으로 치유되지 않는다.

### 9-3. [라운드59 → 60 → 62 이월] 표본 하한 공시 문구의 사실성
