### 🔔 사용자에게 통지 발송 — 결정 #3(b) DB 마이그레이션

`lib/db-cache.ts`(+22) · `lib/molit-api.ts`(+28) · `supabase/schema.sql`(+17)이 **라운드48부터 4라운드째 미커밋**으로 남아 있다. 이는 드리프트가 아니라 **의도된 보류**이며(라운드48 §51, 라운드50이 `git add -p`로 랭킹 hunk만 골라낸 것도 같은 이유), 이번 라운드에도 **커밋하지 않는 것이 맞다**고 판단했다.

**오늘 직접 재확인한 근거** — 운영 DB에 컬럼이 아직 없다:
```
GET /rest/v1/deals?select=cdeal_type,cdeal_day&limit=1
→ HTTP 400  {"code":"42703","message":"column deals.cdeal_type does not exist"}
```
main push = Vercel 자동배포라 **코드가 먼저 나가면 `upsertMonthDeals`가 PGRST204로 실패**한다. 두 호출부 모두 try/catch라 화면은 안 깨지지만 **deals 적재가 조용히 멈추고** 매 조회가 라이브 fetch로 떨어진다.

3라운드간 로그에만 남고 사용자에게 전달된 흔적이 없어, 이번 라운드에 **PushNotification을 발송**했다(데스크톱 전송됨 / 모바일은 Remote Control 비활성으로 미전송). `.env.local`에 Supabase REST 키만 있고 Postgres 직결 문자열이 없어 **DDL은 사용자만 실행할 수 있다.**

**사용자가 Supabase SQL Editor에서 실행할 SQL**(추가 전용, 기존 행·제약·인덱스 무영향):
```sql
alter table deals
  add column if not exists cdeal_type text,
  add column if not exists cdeal_day text;
```
실행 후 알려주시면 다음 라운드가 위 3파일을 즉시 커밋·배포하고 적재를 검증한다.
