### 4-1. 🔴 개발팀 보고의 산술 오류를 QA가 잡았다

| | 실측 |
|---|---|
| `body[7]` 1문장 | 43자 → 50자 = **+7** |

### 9-2. [라운드58 → 59 → 60 이월, 🔴] 광주광역시 캐시 리셋

여전히 미해결이고 여전히 **사용자 조치 1회로 끝난다.** 동결과 무관하고 코드 변경도 불필요하며, 이미 배포된 관리자 엔드포인트에 HTTP 5회다.

```bash
for c in 29110 29140 29155 29170 29200; do curl -s "https://realestate-hub-6n4n.vercel.app/api/admin/reset-cache?secret=$CRON_SECRET&lawd_cd=$c&building_type=아파트"; echo; done
```

`$CRON_SECRET`은 `.env.local` 값(로그에 평문으로 적지 않는다). 지우는 5개 지역 행이 **전부 0건**이라 소실될 데이터가 없다. 마스터가 직접 하지 않는 이유는 스케줄 지시서가 이 **쓰기 동작**을 명시하지 않았기 때문이다.

**결과 판독**: 재수집 후 거래가 잡히면 캐시 오염(종결). 여전히 0이면 `LAWD_FANOUT` 등록이 필요하고 그건 `lib/molit-api.ts`(**동결**)라 9-1 해제까지 대기.

🔴 **인천에는 이 리셋을 쓰지 마라** — §6이 보여주듯 원천 데이터 자체가 없어 리셋으로 치유되지 않는다.
