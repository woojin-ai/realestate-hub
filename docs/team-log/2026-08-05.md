## 4. ⚠️ 라운드59의 "아웃바운드 차단" 진단 부분 정정 — 광주는 여전히 미해결

라운드59는 `apis.data.go.kr`이 **차단(HTTP 000)**이라 광주 원인 판별 불가로 적었다. 재측정 결과 **호스트가 아니라 프로토콜 문제**다.

| 요청 | 결과 |
|---|---|
| `http://apis.data.go.kr/...` (코드가 쓰는 방식) | **HTTP 000** — 샌드박스가 평문 HTTP 차단 |
| `https://apis.data.go.kr/1613000/...` | HTTP **200**이지만 본문이 `<errMsg>HTTP_ERROR</errMsg><returnReasonCode>04</returnReasonCode>` |

**실질 결론은 라운드59와 같다** — 이 샌드박스에서 국토부 API 직접 조회 불가. 다만 사유가 다르다.

- 🔴 **다음 사람 주의: `https`로 200이 떠도 뚫린 게 아니다.** 본문의 `returnReasonCode`를 봐라.
- 🔴 **`lib/molit-api.ts`의 `http://`를 https로 바꾸지 마라** — 게이트웨이가 거부한다(어차피 동결 파일).

**광주 판별 시도도 했으나 실패했다.** 캐시 창(13개월)을 넘는 `months=24`로 질의하면 미캐시 월이 라이브 조회될 것으로 기대했으나, 응답이 `source:"partial"`로 돌아와 **추가 월이 실제로 국토부에서 조회됐는지 증명하지 못했다**(29170·29200 = 0/0, 대조군 26110 = 8/2). **결론 못 냄 — 라운드59 §9-2의 리셋 1회가 여전히 가장 싼 판별기다.**

### 5-1. `body[N]` 오기의 원인 (QA 분석)

발행본 본문은 `0:도입부 · 1:면책콜아웃 · 2:heading · 3:para · 4:heading · 5:para…` 균일 패턴이라 **n번째 본문 문단 = `body[2n+1]`**인데, 기획팀이 균일 패턴 글에서 ±1씩 어긋났다. I1만 정확했던 이유는 I1이 `body[7]`·`body[8]`이 연속 문단인 **예외 구조**라 우연히 상쇄됐기 때문이다. → **다음 라운드가 `body[N]`을 근거로 쓸 일이 있으면 반드시 코드에서 재확인해라.** 라인번호·직전헤딩·축자전문 세 좌표는 9/9 정확했다.
