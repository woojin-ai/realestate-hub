### 7-3. QA 검증 항목 (다음 편에도 그대로 적용)

1. **[정정 · N-2] 축자 대조** — 발행본 인접 글과 **명제(사실 주장) 기준 연속 15자 이상 일치 0건**. **예외**: ① 내부링크 관용구 ② UI 문자열 축자 인용 ③ 공통 면책·신고기한 고지 **④ [2026-08-05 추가] 사이트·기관 고유명사 및 사이트 자칭 명사구를 포함해 잔여 명제 구간이 15자 미만인 경우**(정의·판정 절차는 §2-1-b (나) ④). **측정은 QA 독립 수행이 정본**(이번에 개발팀 보고 "2건·최대 15자" ≠ 실측 "4건·21/19/19/15자").
2. **시점 약속 부재** — "곧", "다음 갱신에", "수집이 끝나면" 류 표현 0건인지 전문 검색.
3. **딥링크 서술 라이브 실증** — `/ranking` **전세 탭**에서 지역명 클릭 → 도착한 대시보드가 **매매 탭·아파트**로 시작하는지 실제 클릭 확인.
4. "왜"에 해당하는 해석 문장이 새로 들어갔는지(§2-1 경계).
5. 지역명·순위·금액·변화율·거래건수 실측값이 0건인지.
6. "빌라"·"단독"·"준비 중인 유형" 표현 0건인지.
7. UI 문자열 인용이 화면과 정확히 일치하는지(§4 표의 라이브 재검산 열).
8. 기존 편 수정 라인이 승인분(상호 참조 1줄)뿐인지, `npm run build`에서 `/blog/[slug]`가 **14편**인지.
9. summary 자수(실측 **84자**, 기존 최장 116자)와 `heading` **11개** = 산출 HTML `<h2>` 11개 일치.
10. **[신규] 기획안 mtime vs 구현 mtime 대조** — 정본이 구현보다 늦게 개정됐으면 그 지시는 "미이행"이 아니라 **사후 판정 대상**으로 분류한다(교훈 2, 이번 라운드 N-1의 발견 경로).
