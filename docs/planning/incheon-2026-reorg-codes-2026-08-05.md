## 1. ⚠️ 라운드59의 "아웃바운드 차단" 진단을 부분 정정한다

라운드59 §3-4·§9-1은 `apis.data.go.kr` 아웃바운드가 **차단(HTTP 000)** 이라 광주 원인 판별이 불가하다고 적었다. 이번에 다시 재 보니 **호스트가 아니라 프로토콜 문제**다.

| 요청 | 결과 |
|---|---|
| `http://apis.data.go.kr` (코드가 쓰는 방식) | **HTTP 000** — 샌드박스가 평문 HTTP를 막는다 |
| `https://apis.data.go.kr/1613000/…/getRTMSDataSvcAptTradeDev?...` | **HTTP 200** (전송 성공) |
| 위 https 응답 본문 | `<errMsg>HTTP_ERROR</errMsg><returnReasonCode>04</returnReasonCode>` |

즉 **전송은 되지만 data.go.kr 게이트웨이가 https 요청을 거부한다**(`lib/molit-api.ts`가 엔드포인트를 `http://`로 하드코딩한 이유로 보인다).

→ **실질 결론은 라운드59와 같다: 이 샌드박스에서 국토부 API를 직접 때릴 수 없다.** 다만 사유가 "호스트 차단"이 아니라 "평문 HTTP 차단 + 게이트웨이의 https 거부"이므로, 다음 사람이 "차단이 풀렸나?" 확인할 때 `https`로 200이 떠도 **뚫린 것이 아니다.** 본문의 `returnReasonCode`를 봐라.

🔴 그리고 이것 때문에 **`lib/molit-api.ts`의 `http://`를 https로 바꾸면 안 된다** — 게이트웨이가 거부한다. (해당 파일은 어차피 동결 중이다.)

## 2. ✅ 신설 4개 구 코드 확보 — 카카오 로컬 API

라운드59가 제안한 경로(code.go.kr / 공공데이터포털)는 이번에도 막혔다: `code.go.kr`은 HTTP 200이지만 코드 조회가 JS 렌더/로그인 기반이고, 추측한 API 경로 2개는 전부 HTML 404였다. 공식 인천시 행정구역 페이지(`incheon.go.kr/IC040102`)는 **2군 9구 구성은 확정해 줬으나 코드는 싣지 않는다.**

## 3. 🔴🔴 그런데 — 국토부 RTMS가 신설 코드를 아직 서비스하지 않는다

코드를 얻었으니 **바로 `regions.ts`에 넣고 싶은 유혹**이 있다. 넣기 전에 실제로 거래가 잡히는지부터 확인했고, 결과가 계획을 뒤집었다.

### 3-1. 시험 방법

이 샌드박스는 국토부 API를 직접 못 때리지만(§1), **배포된 Vercel 앱은 때릴 수 있다.** 그리고 `app/api/data/route.ts`의 입력 검증은 `/^\d{5}$/` 정규식뿐이라 **`regions.ts`에 없는 코드도 그대로 조회**한다. 즉 라이브 앱을 국토부 API 프록시로 써서 코드를 미리 시험할 수 있다.

> 이것은 관리자/파괴적 쓰기가 아니라 **앱의 평상시 읽기 경로**다(방문자가 지역을 열면 매번 일어나는 것과 동일). 라운드59도 같은 엔드포인트로 검증했다.

### 3-2. 실측 (`building_type` 기본=아파트)

| `LAWD_CD` | 지역 | `months=2` | `months=13` | `source` |
|---|---|---|---|---|
| **28177** | 미추홀구 (**대조군**) | 매매 15 / 전세 11 | **매매 30 / 전세 30** | `partial`(캐시 보유) |
| 28125 | 제물포구 (신설) | 0 / 0 | **0 / 0** | `live`(방금 국토부 조회) |
| 28155 | 영종구 (신설) | 0 / 0 | **0 / 0** | `live` |
| 28275 | 서해구 (신설) | 0 / 0 | **0 / 0** | `live` |
| 28290 | 검단구 (신설) | 0 / 0 | **0 / 0** | `live` |
| 28110 | 중구 (폐지) | 0 / 0 | — | `partial` |
| 28260 | 서구 (폐지) | 0 / 0 | — | `partial` |

(숫자는 `aptStatsMaeMae` / `aptStatsJeonse` 행 수)

### 3-3. 판독

- **대조군이 같은 경로·같은 창에서 30/30을 반환한다.** 따라서 0은 "우리 조회가 깨졌다"가 아니라 **국토부가 그 코드로 줄 것이 없다**는 뜻이다.
- `source: "live"`는 캐시가 아니라 **이번에 실제로 국토부를 조회한 결과**다. 캐시 오염 가설이 여기서는 배제된다.
- 신설 4개 코드는 **13개월 창 전체에서 0**이다. 국토부가 과거분을 신설 코드로 소급 재배치하지도 않았다.
- 폐지된 28110·28260도 0이다. → **중구·동구·서구 권역은 현재 어느 코드로도 아파트 거래가 잡히지 않는다.**

### 3-4. 🔴 그래서 라운드59의 다음 행동 계획이 무효다

라운드59 §9-1은 "코드를 확보하면 `lib/regions.ts` 작업"을 P0 다음 행동으로 잡았다. 그 계획에는 **"신설 코드를 넣으면 거래가 잡힌다"는 검증되지 않은 전제**가 들어 있었다. 실측은 그 전제를 반증한다.

**지금 4개를 추가하면 일어나는 일**: 랭킹 보드의 `isPending` 지역이 **9개 → 13개로 늘어난다.** 게다가 `totalRegions`가 114 → 118이 되어 프리워밍 순회 길이와 `prewarm_progress.last_index`의 의미가 밀린다(라운드59 §9-1이 경고한 부작용). **비용은 다 치르고 효과는 0이다.**

### 3-5. 정직한 한계 — 왜 0인지는 모른다

가설 2개를 갈라내지 못했다.

- **(가) 국토부 RTMS의 신규 코드 온보딩 지연** — 행정 개편(07-01)이 실거래가 신고·공개 시스템에 반영되는 데 시차가 있다. 이 경우 시간이 지나면 저절로 나오기 시작한다.
- **(나) 그 권역에 별도 원인이 겹쳐 있다** — 라운드59 §3-3이 이미 지목했듯 **인천 서구는 개편 전 202508~202604 10개월도 공백**이었다. 개편만으로 설명되지 않는 결함이 원래 있었다.

(가)와 (나)는 배타적이지 않다. 판별하려면 **시간을 두고 재조회하는 것**이 유일하게 싼 방법이다.

## 4. 권고 — 코드는 적어 두되 `regions.ts`에는 아직 넣지 않는다

1. **`lib/regions.ts` 수정 보류.** 근거 §3-4. 지금 넣으면 빈 지역만 4개 는다.
2. **이 문서가 코드의 정본이다.** 다음 라운드가 다시 확보 작업을 반복하지 마라 — §2-1 표를 그대로 쓰면 된다.
3. **매 라운드 재조회 1줄로 감시한다.** 아래를 돌려 하나라도 0이 아니게 되는 순간이 "(가) 온보딩 지연"이 끝난 시점이고, 그때 §5의 설계 작업을 시작하면 된다.

```bash
for c in 28125 28155 28275 28290; do printf "%s " "$c"; curl -s --max-time 90 "https://realestate-hub-6n4n.vercel.app/api/data?lawd_cd=${c}&months=2" | grep -o '"aptStatsMaeMae":\[' | wc -l; done
```

4. **폐지 3개 코드(28110·28140·28260)를 지우지 마라** — 라운드59 §9-1의 경고 그대로 유효하다. 과거 달 거래는 그 코드로 수집돼 있어야 정상이다.

## 5. 코드가 살아나면 그때 필요한 설계 (미착수 — 기획 필요)

지금 하지 않지만, 착수 시점에 반드시 함께 풀어야 하는 것들이다.

1. **개편 전/후 시간 분할.** 같은 지리적 장소가 202606까지는 28110, 202607부터는 28125/28155다. 지역 목록에 둘 다 두면 랭킹에 같은 동네가 두 줄로 뜬다. `REGION_CODES`에 유효기간 개념이 없으므로 **구조 변경**이다.
2. **프리워밍 인덱스 이동.** `prewarm_progress.last_index`가 순서 의존이라 목록 중간에 4개를 끼우면 그 뒤 전부가 밀린다. 추가 위치·마이그레이션을 함께 정해야 한다.
3. **1:N 분할의 과거 데이터 귀속.** 옛 중구(28110)의 과거 거래를 제물포·영종 중 어디로 볼 것인가 — 법정동 단위로 갈라야 정확한데, 그 매핑 자체가 별도 작업이다. "과거는 옛 코드로만 보여준다"가 가장 싼 답일 수 있다.

## 6. 사용자께 — §9-1 요청을 **철회**한다

라운드59가 "신설 4개 구 코드를 확보해 주세요"라고 올렸던 P0는 **이번 라운드에 자체 해결됐다**(카카오 로컬 API, §2). 더 이상 사용자 조치가 필요하지 않다.

다만 확보 결과가 좋은 소식만은 아니다 — **코드를 넣어도 인천 4개 구는 지금 복구되지 않는다**(§3). 랭킹 보드의 `isPending` 9개 지역은 당분간 그대로 남는다는 뜻이고, 이건 우리 결함이 아니라 **원천 데이터가 아직 없는 것**이다.
